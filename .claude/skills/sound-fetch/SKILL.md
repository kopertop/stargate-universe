# Sound Fetch Skill

Search CC0 sound sources for game audio, download into the project's `sounds/` dir,
import them so Godot can load them, and wire into the game.

> **Engine note:** This project is **Godot 4.6** (see CLAUDE.md). Audio assets live
> **in the repo** under `sounds/` as committed `.ogg`/`.wav` files (the Kenney kit
> convention) — there is no R2 bucket and audio is NOT excluded from git. Every clip
> needs its `.import` sidecar generated by `godot --headless --import`, or
> `Audio.play()` / `load()` silently fails. SFX route through the **`Audio` autoload**
> (`scripts/audio.gd`); the music bed routes through `MusicDirector`.

## Primary Source: soundcn.xyz

**soundcn** is a CC0 sound library with an npx CLI (similar to shadcn for UI components).

- **Website**: https://www.soundcn.xyz/
- **GitHub repo**: https://github.com/kapishdima/soundcn
- **Sound registry**: https://github.com/kapishdima/soundcn/tree/main/registry/soundcn/sounds

### Local Sound Registry (preferred — fastest)

The soundcn GitHub repo contains all sound files in `registry/soundcn/sounds/`.
A local clone lives at `assets/soundcn-registry/` for instant access:

```bash
# One-time setup (if not already cloned):
git clone --depth 1 https://github.com/kapishdima/soundcn.git /tmp/soundcn-repo
cp -r /tmp/soundcn-repo/registry/soundcn/sounds/ assets/soundcn-registry/
rm -rf /tmp/soundcn-repo
```

To find sounds locally:
```bash
ls assets/soundcn-registry/          # List all sound categories
ls assets/soundcn-registry/impact/   # List impact sounds
find assets/soundcn-registry/ -name "*metal*" -o -name "*spark*"  # Search by keyword
```

### CLI Install (alternative)

```bash
npx shadcn@latest add @soundcn/<package-name>
```

Note: Requires `components.json` — if not configured, use the local registry instead.

Examples:
```bash
npx shadcn@latest add @soundcn/impact-metal-000
npx shadcn@latest add @soundcn/ambient-hum-001
npx shadcn@latest add @soundcn/ui-click-003
```

### Browsing soundcn.xyz

Use browser automation (claude-in-chrome) to:
1. Navigate to `https://www.soundcn.xyz/`
2. Browse categories or search for the described sound
3. Identify the package name (e.g. `@soundcn/impact-metal-000`)
4. Present candidates to the user via `AskUserQuestion`
5. Download from local registry or via CLI

### After soundcn download

Sound files from any source must be:
1. Converted to `.ogg` if needed (see Format Guidelines)
2. Placed in the project's `sounds/` dir (see Step 6)
3. Imported with `godot --headless --import` so the `.import` sidecar exists
4. **Committed to git** alongside their `.import` sidecar (Godot project assets live in-repo)

## Workflow

### Step 1: Understand the Request

Parse the argument to determine:
- **Sound category**: SFX, ambient, music, UI, voice
- **Context**: What game system/feature needs this sound
- **Desired format**: Default to `.ogg` (Vorbis) — Godot imports it natively and it loops cleanly

If the argument looks like a soundcn package name (e.g. `@soundcn/...`), skip search and go directly to install.

### Step 2: Search for Sounds

**soundcn (preferred):**
1. Browse `https://www.soundcn.xyz/` using browser tools
2. Search or browse categories for matching sounds
3. Note the `@soundcn/<package>` names

**Other sources:**
Use browser automation or ask the user for a direct URL.

Present the top 3-5 candidates to the user via `AskUserQuestion`:
- Include: name, duration, source, preview info

### Step 3: Download the Sound

**From soundcn:**
```bash
npx shadcn@latest add @soundcn/<package-name>
```

**From URL:**
Download to temp location:
```bash
curl -L -o /tmp/sgu-sounds/<filename> <url>
```

### Step 4: Convert and Normalize

If the file is not `.ogg`, convert using ffmpeg. This project's ffmpeg often lacks
`libvorbis`, so use the built-in experimental Vorbis encoder (`vorbis -strict -2`):
```bash
ffmpeg -i input.wav -c:a vorbis -strict -2 -q:a 4 output.ogg
```

Normalize audio levels (optional, for one-shots that are too hot/quiet):
```bash
ffmpeg -i input.ogg -af loudnorm -c:a vorbis -strict -2 output-normalized.ogg
```

For seamless loops (ambient/music), see the `music` / `sound-effects` skills and the
`ffmpeg-crossfade-loop` skill rather than hand-rolling the loop here.

### Step 5: Name and Categorize

Apply the project naming convention (snake_case files, per CLAUDE.md):
- **Path**: `sounds/<name>.ogg` (the kit keeps audio flat in `sounds/`; sub-folders like
  `sounds/dialog/...` exist for voice — match the neighbours of similar clips)
- **Names**: snake_case, descriptive (e.g. `repair_sparks.ogg`, `door_hiss.ogg`)

Ask the user to confirm the name and location if ambiguous.

### Step 6: Place in `sounds/` and Import

Copy the finished clip into the project (it stays in git — Godot assets are in-repo):
```bash
cp /tmp/sgu-sounds/<file> sounds/<name>.ogg
```

**Generate the `.import` sidecar** — without it `Audio.play()` / `load()` silently fails
(same trap as PNGs without their sidecar):
```bash
godot --headless --import        # GODOT_BIN=/path/to/godot if not on PATH
```

Confirm `sounds/<name>.ogg.import` now exists. Stage both the `.ogg` and its `.import`.

### Step 7: Wire into Game (Godot)

1. **Reuse the `Audio` autoload** (`scripts/audio.gd`) — it's a pooled one-shot SFX bus.
   There is no per-sound catalog/registry; clips are referenced by `res://` path.

2. **Play a one-shot** from the relevant system (room, interactable, quest step):
   ```gdscript
   Audio.play("res://sounds/<name>.ogg")
   ```
   For a centralised, swappable trigger (e.g. the UI hover blip), follow the
   `UI_HOVER_SOUND` const + `play_ui_hover()` / `attach_ui_hover()` pattern already in
   `scripts/audio.gd` rather than scattering raw paths.

3. **Positional (3D) audio**: add an `AudioStreamPlayer3D` to the emitting node/scene,
   set its `stream` to the imported clip, and route it to the `SFX` bus. Use this for
   sounds that should attenuate with distance (a sparking conduit, a humming console).

4. **Ambient / music beds** route through `MusicDirector` (+ `data/music_moods.json`),
   not `Audio` — see the `music` skill.

5. **Present the integration** to the user for approval before writing.

### Step 8: Verify

- Run a headless boot / the smoke suite to confirm nothing broke and the clip imports:
  ```bash
  tests/run.sh scene      # scene-boot; or `tests/run.sh` for the full suite
  ```
- Confirm the `.import` sidecar is present (Step 6) — a missing sidecar is the #1 cause
  of "the sound doesn't play" with no error.
- Report: sound name, `res://sounds/...` path, trigger location, and playback settings.

## Audio Format Guidelines

| Category | Format | Sample Rate | Channels | Notes |
|----------|--------|-------------|----------|-------|
| SFX      | ogg    | 44.1kHz     | Mono     | Short, one-shot |
| Ambient  | ogg    | 44.1kHz     | Stereo   | Looping, crossfade |
| Music    | ogg    | 44.1kHz     | Stereo   | Looping or one-shot |
| UI       | ogg    | 44.1kHz     | Mono     | Very short, responsive |
| Voice    | ogg/wav| 44.1kHz     | Mono     | Dialogue, announcements, radio chatter |

`.ogg` (Vorbis) is the default; `.wav` is fine for short SFX/voice where size is a
non-issue. Encode Vorbis with `vorbis -strict -2` (this ffmpeg often lacks `libvorbis`).

## Project Audio Path Convention

All sounds live **in the repo** under `sounds/` (committed to git, with their `.import`
sidecars). The kit keeps clips flat; voice lines are grouped in sub-folders:
```
sounds/
  *.ogg                    # SFX, ambient, UI (e.g. bong_001.ogg, door_hiss.ogg)
  dialog/                  # Voice lines, grouped by scene
    prologue/  standoff/   # e.g. open-*.wav, baked TTS lines
```
Reference clips by `res://sounds/<name>.ogg` — there is no remote bucket or asset
resolver. Run `godot --headless --import` after adding any file.

## Example Usage

```
/sound-fetch @soundcn/impact-metal-000
/sound-fetch repair sparks — metallic welding sparks for conduit repair
/sound-fetch door hiss — pneumatic door opening/closing sound
/sound-fetch ambient ship hum — low frequency Destiny background hum
/sound-fetch voice ship announcement — Destiny automated warning klaxon
```
